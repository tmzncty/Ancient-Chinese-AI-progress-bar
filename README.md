# Ancient-Chinese-AI-progress-bar

> 古文 AI 不是一个进度条，而是一组进度条。
>
> 这个仓库持续记录 **古籍数字化、古代汉语处理、古典文献研究辅助** 的真实能力边界：哪些已经能用，哪些只能辅助，哪些仍然离“交给机器”很远。

**Last calibrated: 2026-08-28**

本项目最初写于 2023 年。当时重点还是 ChatGLM/RWKV 微调、OCR 与“要不要训练一个古文模型”。三年后，问题已经发生了变化：古文专用预训练模型、古籍领域大模型、任务基准、共享评测和多模态模型都已经出现；真正需要持续追踪的，不再是“有没有模型”，而是 **模型在具体任务上到底可靠到什么程度**。

因此从 2026 版开始，本仓库不再给“古文 AI”一个笼统百分比，而采用任务矩阵 + 证据校准。

## 0. 怎么读这个进度条

### 能力等级

| 等级 | 进度条 | 含义 |
|---|---|---|
| 0 | `░░░░░` | 尚未形成可重复方案 |
| 1 | `█░░░░` | 有 demo / 个例，泛化能力未知 |
| 2 | `██░░░` | 有公开数据、模型或基准，但离稳定使用较远 |
| 3 | `███░░` | 在限定材料上已经实用，但仍需要人工复核 |
| 4 | `████░` | 在边界明确的工作流中可以作为常规工具 |
| 5 | `█████` | 高度成熟，可大规模自动化且错误边界清楚 |

这里的等级不是“模型聪明程度”，更不是营销评分。更新等级至少需要一种可检查的证据：公开评测、共享任务、论文实验、可复现实验或持续的真实工作流。

**本仓库刻意不计算总进度。** OCR、断句、训诂、命名实体识别、文白翻译、版本校勘和文学阐释并不是同一道题，把它们平均成“古文 AI 已完成 73%”只会制造虚假的精确感。

机器可读版本见 [`progress.yaml`](./progress.yaml)。

## 1. 2026 能力仪表盘

### 1.1 从书页到文本

| 任务 | 状态 | 当前判断 | 主要瓶颈 |
|---|---:|---|---|
| 古籍版面分析 | `███░░` 3/5 | 已能识别文本区、图像、书口、印章等版面元素，但复杂刻本仍需校核 | 异形版式、栏线、夹注、破损、跨页结构 |
| 刻本文字 OCR | `███░░` 3/5 | 已进入多模态大模型与专用 OCR 并行阶段，可用于初稿转录 | 异体字、缺字、污损、行序、罕见字 |
| 手稿 / 抄本 OCR | `██░░░` 2/5 | 已有专门评测，但个体书写差异仍显著拉低可靠性 | 草写、连笔、涂改、俗字、个体字形 |
| 异体字 / 字形归一 | `██░░░` 2/5 | 可以做候选映射，但“识别原字”与“规范化”为两个任务，不能混成一次替换 | 字形知识、版本差异、Unicode 缺字 |

**为什么 2026 年还不能把 OCR 写成“解决了”？** 2026 年 EvaHan 已经把古籍 OCR 拆成刻本文字识别、版面元素分析、手写识别三个任务，并以 CER、F1、NED、mAP、IoU 等指标分别评测。这本身说明“把古籍图片变成干净文本”仍是一个多阶段系统问题，而不是单个 OCR 按钮。

### 1.2 从文本到结构

| 任务 | 状态 | 当前判断 | 主要瓶颈 |
|---|---:|---|---|
| 分词 / 词性标注 | `███░░` 3/5 | 已有长期研究与共享评测，可作为下游分析组件 | 古汉语“词”的边界本身具有分析性 |
| 断句 / 标点 | `███░░` 3/5 | 对常见文体已有较强辅助价值 | 专名、引文、韵文、异文、编辑学选择 |
| 命名实体识别 NER | `███░░` 3/5 | 人名、地名、书名等已经可进行规模化预标注 | 跨时代命名习惯、别名、同名、实体类型体系 |
| 关系抽取 RE | `██░░░` 2/5 | 已有古代史专门语料与实验，但领域依赖仍强 | 隐含关系、长距离依赖、知识补足 |
| 句法 / 依存分析 | `██░░░` 2/5 | 有可用工具链，但不同文体与时代的稳健性有限 | 省略、活用、兼类、分析体系差异 |

EvaHan 的任务变化很有代表性：

- **2022**：古代汉语分词与词性标注；
- **2023**：古代汉语机器翻译；
- **2024**：断句与标点；
- **2025**：命名实体识别；
- **2026**：多模态古籍 OCR。

这条时间线比“参数越来越大”更适合描述古文 AI 的实际进展：研究开始从单纯语言建模，逐步进入 **任务基准化、专业化和多模态化**。

### 1.3 从结构到理解

| 任务 | 状态 | 当前判断 | 主要瓶颈 |
|---|---:|---|---|
| 文白翻译 | `███░░` 3/5 | 普通材料已非常适合做初译、对照与改写，但不能等同于定本释义 | 多义、典故、制度语境、省略成分 |
| 字词义项 / 语法解释 | `███░░` 3/5 | 在给定上下文中可以高效提出候选解释 | 容易把“合理解释”误写成“有证据的解释” |
| 古文问答 / 阅读理解 | `███░░` 3/5 | 专门 benchmark 已经形成，专用模型也能取得明显提升 | 幻觉、知识泄漏、跨篇章证据链 |
| 有出处约束的检索问答 | `███░░` 3/5 | 配合可靠全文库、检索和逐条引用后非常有研究辅助价值 | 版本选择、召回率、引文对齐、错误归因 |
| 历史信息抽取 | `███░░` 3/5 | 已有跨 13 个朝代、覆盖 1830 余年的 CHisIEC 等资源 | schema 依赖、隐含关系、跨文本实体消歧 |

这里最重要的分界不是“模型会不会回答”，而是：

> **它能不能告诉你答案依据哪一版、哪一句、哪一个可复核证据。**

对于研究场景，能生成十段漂亮解释，通常不如能稳定找出三条例证并把出处标对。

### 1.4 从理解到文献学判断

| 任务 | 状态 | 当前判断 | 主要瓶颈 |
|---|---:|---|---|
| 音—形—义关联分析 | `██░░░` 2/5 | 多源数据可以被统一检索和辅助联想，但模型本身不是音韵学或文字学证据 | 历史层次、拟音体系、字形谱系、材料异质性 |
| 版本校勘 / 异文判断 | `██░░░` 2/5 | 自动对齐、异文发现已经很有用；“哪个字应当取”仍高度依赖专家判断 | 版本谱系、讹衍倒脱、避讳、后人改写 |
| 训诂证据发现 | `██░░░` 2/5 | 适合做大规模候选检索和相似用例发现 | 时代错配、义项漂移、循环论证 |
| 跨文献事实综合 | `██░░░` 2/5 | 可明显降低资料搜集成本，但综合结论仍易出现来源混淆 | 同名异人、纪年转换、互文与冲突记载 |
| 自动形成可发表的文献学结论 | `█░░░░` 1/5 | 不应作为当前目标宣传 | 证据责任、可证伪性、学术史与方法意识 |

这也是本项目对“AI 理解古文”的核心保留：**语言流畅 ≠ 文献学判断可靠。**

---

### 1.5 多模态中国古典学

状态：`██░░░` **2/5**

古典学并不只有纯文本。书法、绘画、甲骨、印章、器物、插图、版式都要求视觉与文本知识共同工作。2025 年 ACL 的 **MCS-Bench** 将中国古典学拆成 7 个子领域、45 个任务，对 37 个多模态大模型进行评测；论文报告中，最佳模型平均分仍低于 50。

这意味着多模态模型已经“能进场”，但离稳定承担古典学判断还有明显距离。

## 2. 2023 版中需要修正的几个判断

这个仓库保留 Git 历史，不删除 2023 年的观察。但有几条旧判断现在已经不适合作为结论。

### 2.1 “未断句、无标点文本基本不能作为数据集”——不成立

无标点文本当然可以作为语言模型预训练数据，也可以直接用于序列建模。是否需要标点，取决于训练目标：

- 做原始语言建模，不要求先人工标点；
- 做断句/标点，需要成对的监督数据或可构造标签；
- 做问答、翻译、信息抽取时，标点通常能降低工程难度，但不是数据“存在”的前提。

更重要的是，古籍标点本身带有编辑判断。机器标点不是把“客观存在的逗号”找回来，而是在很多情况下提出一种现代整理方案。

### 2.2 “古文主要为单音节字词”——过度简化

古代汉语确实具有较强的单音节倾向，但不能因此把“字”和“词”直接视为同一单位。复音词、固定结构、专名、虚词组合，以及不同历史阶段的词汇化过程都要求更谨慎的分析。

所以本项目以后会分别记录：**字符、词、短语、实体、句法结构**。

### 2.3 “AI 作诗没有意境”——不是一个可直接验证的技术指标

“意境”是文学批评概念，不适合直接充当模型内部机制的判定标准。更可操作的研究问题包括：

- 是否满足格律 / 韵律约束；
- 是否出现套语、拼贴、时代错置；
- 人类读者如何评价风格一致性与新颖性；
- 是否能解释自己的用典来源；
- 是否能在指定诗学规范下稳定生成。

因此本仓库**不为“悟性”设置百分比**。文学判断可以研究，但不假装它和 OCR 的 CER 是同一类指标。

### 2.4 “做古文 AI = 自己预训练大模型”——已经过时

2023 年把硬件需求按“从零预训练 / 微调 / 推理”来写，在当时很自然；今天则需要把路线拆开：

1. 直接调用通用大模型；
2. RAG / 全文检索 + 大模型；
3. 小模型或编码器做 NER、断句、分类等专门任务；
4. LoRA / SFT 做领域适配；
5. 继续预训练领域模型；
6. 多模态 OCR / layout 模型；
7. 真正从零预训练。

大多数古典文献研究项目根本不需要走到第 7 步。

## 3. 已经出现的代表性资源

这不是“排行榜”，只列用于校准本项目判断的公开资源。

### 评测与数据

- **EvaHan** — 古代汉语处理国际评测；2022–2026 已覆盖分词/POS、翻译、标点、NER、多模态 OCR。  
  https://github.com/GoThereGit/EvaHan
- **ACLUE** — Ancient Chinese Language Understanding Evaluation，覆盖词汇、句法、语义、推理、知识等 15 类古文理解任务。  
  https://github.com/isen-zhang/ACLUE
- **CHisIEC** — 古代中国历史信息抽取语料，包含 14,194 个实体、8,609 个关系，材料跨 13 个朝代。  
  https://aclanthology.org/2024.lrec-main.283/
- **MCS-Bench** — 面向中国古典学的多模态评测，覆盖古文、书法、绘画、甲骨、印章、文物、插图。  
  https://aclanthology.org/2025.acl-long.1063/ （如 ACL 编号调整，以论文题名检索为准）

### 模型与工具

- **GuwenBERT** — 基于古文语料继续训练的 RoBERTa 系列模型，早期古文 NER / 序列标注的重要基线。  
  https://github.com/Ethan-yt/guwenbert
- **XunziALLM / 荀子** — 面向古籍处理的系列语言模型，已覆盖 Qwen、ChatGLM、Baichuan 等多种基座。  
  https://github.com/Xunzi-LLM-of-Chinese-classics/XunziALLM
- **WenyanGPT + WenyanBENCH** — 2025 年 IJCAI 工作，针对 Classical Chinese 继续预训练与指令微调，并提供专门 benchmark。  
  https://www.ijcai.org/proceedings/2025/927
- **UD-Kanbun** — 持续维护的古典汉文 tokenizer / POS tagger / dependency parser 工具链。  
  https://github.com/KoichiYasuoka/UD-Kanbun

> 收录在这里，不等于本项目为其结果背书。所有模型效果都应回到具体版本、数据集和任务上讨论。

## 4. 一个更实际的古籍 AI 工作流

如果目标是“帮助研究者处理一批古籍”，2026 年更值得搭建的是流水线，而不是先训练一个会聊天的“古文大师”。

```text
古籍扫描 / 照片
      │
      ▼
版面分析 ──► 行/栏/夹注/图像/印章定位
      │
      ▼
OCR / 手写识别
      │
      ├──► 保留原始转录（不擅自规范化）
      │
      ▼
异体字映射 / Unicode / 缺字处理
      │
      ▼
断句与标点（保留模型置信度与人工修改）
      │
      ├──► NER / 关系抽取 / 时间地名规范化
      │
      ├──► 全文索引 / 向量检索 / 相似例句
      │
      └──► 文白翻译 / 释义 / 问答
                    │
                    ▼
             出处、版本、页码回链
                    │
                    ▼
                 人工判断
```

这里最重要的不是最后那个聊天框，而是：**每一步都能回到原图、原文、版本和修改记录。**

## 5. 对研究者来说，AI 最有价值的地方

我现在更愿意把古文 AI 看作一种“扩大可检查范围”的工具。

它最适合做：

- 一次看几百万字，帮你找可能相关的例子；
- 把 OCR 初稿变成可检索文本；
- 给专名、断句、关系做预标注；
- 在多个数据库之间寻找可能的对应项；
- 把“我记得 somewhere 有这种用法”变成候选出处列表；
- 把重复性整理工作压缩到人工只处理疑难项。

它最不应该假装做：

- 没有版本依据却给出唯一正确的训诂；
- 不展示证据就宣布某异文“必然为讹”；
- 把现代常识补进古代材料后再当成原文含义；
- 用一段流畅生成文字代替文献出处；
- 把模型自信度当成学术置信度。

## 6. 更新规则

以后每次更新一个能力等级，建议在 PR / Issue 中至少回答四个问题：

1. **任务是什么？** 不要只写“古文理解变强了”。
2. **材料是什么？** 刻本、抄本、先秦散文、正史、诗歌、医籍不能混为一谈。
3. **证据是什么？** benchmark、论文、公开 demo、复现实验还是实际项目？
4. **失败在哪里？** 如果看不到失败案例，就还不能判断它是否进步。

详细贡献规范见 [`CONTRIBUTING.md`](./CONTRIBUTING.md)。

## 7. 关于项目名称

仓库仍然叫 **Ancient-Chinese-AI-progress-bar**，但“progress bar”现在更像一个玩笑式界面：

```text
古籍 AI 总进度：      [无法计算]
刻本 OCR：            ███░░
断句标点：            ███░░
文白翻译：            ███░░
NER：                 ███░░
校勘判断：            ██░░░
自动成为乾嘉学者：    █░░░░  （请勿据此投稿）
```

如果这个项目最后能证明一件事，大概不是“AI 终于读懂了所有古文”，而是：

> **过去很多只能靠人从头翻到尾的工作，现在可以先让机器把值得看的地方举出来；而真正困难的部分，也因此变得更清楚了。**
